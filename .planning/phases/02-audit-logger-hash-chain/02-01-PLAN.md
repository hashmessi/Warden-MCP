  <read_first>src/audit/types.ts, src/seed/postgres.seed.ts</read_first>
  <action>Create `src/audit/logger.ts`. Export a class `AuditLogger`.
1. Implement a static `hashIdentifier(identifier: string): string` method that uses Node.js `crypto.createHash('sha256')` to hash the raw subject identifier (like email) so raw PII isn't stored.
2. Implement `canonicalize(action: string, actor: string, subjectHash: string | null, details: any, prevHash: string): string`. It should deterministic-stringify the data. For simplicity, use `JSON.stringify({ action, actor, subjectHash, details, prevHash })`.
3. Implement `appendLog(params: CreateAuditEntryParams): Promise&lt;AuditEntry&gt;`.
It should:
- Hash the `params.subject` if provided.
- Fetch the last hash from `audit_log` (or 'GENESIS' if empty).
- Calculate the new hash = SHA-256 of the canonicalized string.
- Insert using a query that enforces integrity. Use this exact query pattern:
```sql
WITH last_log AS (
  SELECT hash FROM audit_log ORDER BY id DESC LIMIT 1
)
INSERT INTO audit_log (action, actor, subject_hash, details, prev_hash, hash)
SELECT $1, $2, $3, $4, COALESCE((SELECT hash FROM last_log), 'GENESIS'), $5
WHERE $6 = COALESCE((SELECT hash FROM last_log), 'GENESIS')
RETURNING *;
```
($1=action, $2=actor, $3=subjectHash, $4=details, $5=newHash, $6=expectedPrevHash).
If the insert returns 0 rows, throw an Error("Hash chain integrity violation: prev_hash mismatch").</action>
  <verify>npx tsc --noEmit</verify>
  <acceptance_criteria>
    - `src/audit/logger.ts` uses `crypto.createHash('sha256')`
    - `appendLog` uses an `INSERT ... SELECT ... WHERE` query to enforce `prev_hash` integrity at insert time
    - Raw `subject` is hashed before insertion, avoiding raw PII storage
  </acceptance_criteria>

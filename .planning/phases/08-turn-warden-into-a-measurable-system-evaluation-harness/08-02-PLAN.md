# Plan 08-02: 11 Automated Failure Scenarios & Concurrency Suite

## Objective
Implement all 11 core evaluation scenarios in `src/eval/scenarios/` covering happy path, missing records, idempotent duplicate requests, stale/consumed token guards, denial lockouts, double-approval and double-execution race conditions, distributed partial failures with compensation, rollback failure handling, audit tamper detection, and multi-agent concurrency.

<read_first>

  - src/eval/types.ts
</read_first>
<action>
Create `src/eval/scenarios/race-conditions.ts` (EVAL-10):
- **Double Approval Test:**
  - Create pending action token.
  - Launch 5 parallel `Promise.allSettled([approveAction(token), approveAction(token), ...])`.
  - Assert that exactly 1 returns success (or all return idempotently) and approval store status is strictly `approved`.
- **Double Execution Test:**
  - Seed subject and approve action.
  - Launch 2 concurrent execution attempts simultaneously: `Promise.allSettled([executeAction(token), executeAction(token)])`.
  - Assert that exactly 1 succeeds in executing the deletion; the other is rejected or returns the existing execution ID.
  - Assert duplicate execution count = 0 and INV-02 is satisfied.
</action>
<acceptance_criteria>
- File `src/eval/scenarios/race-conditions.ts` exists.
- Race conditions under `Promise.allSettled` produce exactly 1 mutation without database unique-key constraint crashes.
</acceptance_criteria>
</task>

</action>
